## 2. 根因（PE 已证）

Client_1 `BeiDou.exe` @`7FEEC2`：

```
85 F6          test esi,esi
74 15          jz 7FEEDB
8B 4D DC       mov ecx,[ebp-24h]
8B 55 EC       mov edx,[ebp-14h]   ; ← 关键
33 C0          xor eax,eax         ; 7FEECC
33 FF          xor edi,edi
39 3C 11       cmp [ecx+edx],edi   ; special has_item
```

ae 的 `DrawForceNormalBp52_53_cave`：

- BP52\|53：`xor esi` → `7FEEDB`（OK）
- 其它 BP 且 `esi≠0`：只重放 `mov ecx,[ebp-24h]`，**跳到 `7FEECC`，漏掉 `mov edx,[ebp-14h]`**
- → `cmp [ecx+edx],edi` 用脏 edx → UI 线程故障 / E 未响应

为何「六戒看起来能用」：

| 路径 | 是否经过 ForceNormal special |
|------|------------------------------|
| GetItem/SetItem / 拖拽穿戴 / 属性 | 否 → 可正常 |
| 按 E → CUIEquip 画图标循环 | **是**（每个 esi≠0 的槽）→ 卡死 |

与 −52/−53 是否有物品无关：任意已装备槽走 special 即可触发。ae 修好了 ad 的 BP54，却**真正装上了**有缺陷的 ForceNormal（ad 因 VA=`7FEEC5` 从未装上）。

## 3. af 修复

| 项 | 做法 |
|----|------|
| ForceNormal special | 在 continue `@7FEECC` 前补 **`mov edx,[ebp-14h]`** |
| 其余 | 保持 ae：max=53、bind ON、DrawHasItem edi=item*、−52 gap / −53 shadow |

未关 `kBindExtraRingInventory`（不必回退整段六戒）。
