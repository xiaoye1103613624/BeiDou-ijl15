## 3 与 4 是否不同逻辑？

## 根因（已用 SQL 证明）
- `xiaoye1` char1：`position IN (-52,-53)` **库里一直有**（例：−52→1113069，−53→1113074）。
- **不是没落库**。登录 `getCharInfo` 已编码 52/53；aq 已把 apply-max 强制到 55。
- −52 的 SetItem 写进 Char 空隙后，角色重建 / TSecType 邻域初始化会冲掉；局内穿戴包再写一次又能看见。
- −53 写 DLL 影子，重登不受 Char 布局影响 → 看起来「只有 3 丢」。
